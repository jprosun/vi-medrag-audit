## What this file is for

The RIVF 2026 paper's headline numbers are **label-free mechanical counts** over these
questions: was a claim's supporting span located inside the chunk it cites, was that
chunk's source openable, was a figure inside a verified span, what did enforcement
withhold. No relevance judgement is ever made against these questions, so the file
carries **no gold chunks, no qrels, no expected answers, no must-have concepts and no
reference scores** — and, unlike a labelled benchmark, its size is limited only by
compute rather than by annotation hours. That is the reason a set this size could exist
at all in the time available.

## THIS FILE CARRIES NO LABELS, AND STILL HAS EXACTLY ONE WAY TO BIAS A RESULT

Each row is exactly four keys:

```
{"query_id": ..., "question": ..., "source": "rivf_grid_v2:<specialty>/<question_type>", "rationale": ...}
```

Because nothing here is labelled, the usual contamination worry — that gold labels were
attached to questions chosen with knowledge of the ranker — does not apply. **The one
channel that remains is the topic mix.** A question phrased as a patient FAQ pulls
patient-education chunks, which in this corpus carry no source URL at all; a question
phrased as a study-result lookup pulls journal articles, which do. Both are legitimate
questions, and they move the citability numbers in opposite directions. So:

- the grid was fixed **before** authoring, not chosen after seeing results;
- the file was hashed and committed **before** any condition was run;
- every headline number is reported **per stratum** as well as pooled;
- the paired comparisons the paper leads with (no-gate vs shipped, on identical
  generations) **cannot be moved by question choice at all** — only the absolute levels
  can, and those are always reported with their per-stratum breakdown.

**Do not edit this file.** Re-run `python benchmark/rivf/build_probe_set.py --verify`
to confirm the hash still matches what a result artifact recorded. A question set that
was edited after a run has no pre-registration value, and its results would have to be
discarded rather than corrected.

### The 15 out-of-corpus controls

These are **abstention controls**, not filler. Each is a well-formed clinical question
that a corpus of Vietnamese journal articles and patient-education pages is not expected
to answer with evidence, by one of four mechanisms: it needs a publication date or a
recency judgement (this corpus has no populated date field at all); it asks about a
population or a national programme outside the corpus's scope; it asks for a quantity
that would only exist in a registry or trial; or its premise is subtly false. The correct
behaviour is to abstain or to say the evidence is missing, so these measure whether the
system refuses honestly rather than improvising. They are reported as their own stratum
and never pooled into a general abstention rate.

## How the questions were written, and the limitation that follows

Thirteen agents authored in parallel — twelve specialties plus the control set — each
instructed to write **blind**: from general medical knowledge only, with no repository
access, no web search, and no tool use of any kind. No question was written by looking at
retrieved text, at the corpus, or at any system output. That rules out the strongest form
of leakage, where questions are generated from the very documents they will retrieve, and
it is why `benchmark/synthetic_gold_pipeline/` (which generates questions *from* seed
articles) was deliberately not used.

**The limitation this leaves is stated rather than hidden: these questions are
author-generated, not drawn from a public benchmark.** A reviewer may reasonably say the
authors chose the topic mix. The mitigations are the four bullets above, plus publishing
this file with the paper. Sampling from a public Vietnamese medical question pool would be
strictly stronger and is the right move for a future version.

## Audit, and what it changed

Three independent auditors read the assembled set: a **leakage** auditor (does any
question name a study, journal, institution, dataset, or otherwise pre-select a source,
or embed its own answer), a **language** auditor (natural Vietnamese, correct diacritics
and terminology, medically well-formed), and a **grid** auditor (near-duplicates,
mislabelled question types, clustering on one disease). They raised 64 findings between
them, of which:

- **1 question dropped** — a hepatitis-B-and-breastfeeding question in `truyen_nhiem`
  that duplicated one already written in `tieu_hoa`;
- **18 questions edited**, the substitution and its reason recorded per row in the
  manifest. Examples: a paediatric respiratory-rate question that had copied the
  WHO/IMCI age bands verbatim (leakage), a heart-transplant survival question that named
  a national registry (leakage), a low-back-pain question whose phrasing was not
  idiomatic Vietnamese (language), and four questions labelled `clinical_explainer` that
  contained no "why" component at all (grid);
- **1 edit superseded** — two auditors demanded a change to the same question; the first
  was applied and the second is recorded in the manifest rather than discarded;
- **44 notes** recorded without action.

The builder refuses to write the file if an audit directive quotes a question that is not
in the set, or demands an edit without supplying a replacement. Both would otherwise look
exactly like a clean run.

## Mechanical rules the file passed

- **Disjoint from every set the system was tuned on.** `medqa_topic_gold_v2.jsonl` is
  dev-only by this project's decontamination rule — the removed per-question scoring
  literals were tuned into those 24 questions — and `determinism_queries_v1.jsonl` copies
  24 of them verbatim. Disjointness is checked on exact text *and* on a normalised form,
  because a rephrasing of a tuned question is still a tuned question.
- **No internal near-duplicate pair** above Jaccard 0.72 on normalised tokens. Note that
  this lexical check did *not* catch the duplicate the grid auditor found: two questions
  can ask the same clinical thing in different words. The lexical check and the auditor
  cover different failures and both are needed.
- Unique `query_id`, non-empty question, no surrounding whitespace, at least one
  Vietnamese diacritic per question.

Normalisation keeps diacritics, for the same reason `app/span_norm.py` does: two
Vietnamese words can differ by tone alone, and folding tone marks would report distinct
questions as duplicates.

## Known limits

- 134 questions is a sample size for **mechanical rates**, not for anything requiring
  labels. No retrieval or answer-quality metric may be computed from this file.
- The topic mix is the authors' grid. It is published so a reader can judge it.
- The `rationale` field records what a question is in the grid *for*. It is never an
  answer and never names an expected source; do not treat it as one.
- Out-of-corpus controls are expected to abstain. If a future corpus covers them, they
  stop being controls and the stratum must be rebuilt rather than reinterpreted.
